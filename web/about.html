What is STELLAR?

“System for Time-shared Execution on Low-Level Architecture Resources”

STELLAR-1802 is a multitasking language layer for the RCA COSMAC 1802, a microprocessor from 1976. It sits between the bare chip and the programs you write: instead of 1802 machine code, a STELLAR program is a list of STELLAR commands, and STELLAR's firmware carries them out. Up to four programs run at once, each in its own virtual machine (VM) with its own registers, memory and position in its code, while one 1802 shares its time among them.

The 1802 is an unusual microprocessor chip. It is 8-bit, with sixteen 16-bit registers but no stack instructions, no call or return instruction, no multiply and no divide. STELLAR fills those gaps for its programs: they get calls and returns, stacks, 16- and 32-bit arithmetic with multiply and divide, decimal printing, strings, a terminal, the front panel and the clock, as about two hundred ready-made commands.

1How it works

A program is bytecode. Each STELLAR command is one byte saying what to do, often followed by a byte or two saying what with: 11 05 00 0A loads 10 into register R5, C1 0F prints the string register RF points at. The full set is in the opcode reference.

The firmware is an interpreter. It fetches a VM's next command, looks it up in a dispatch table, and runs the 1802 routine that carries it out. One command costs the chip roughly 190 of its own instructions: fetching and dispatching, the scheduler's bookkeeping, the calls between routines, and the work itself.

Each VM is a block of memory. Everything a VM knows (sixteen 16-bit registers, its accumulators, its flags, its place in its code) lives in a 256-byte core. Its program lives in its own 4 KB program block. Switching from one VM to another is just pointing the firmware at a different core. The VM Core page shows one core live.

The scheduler takes turns. Each running VM gets a short turn of a few commands (its quantum), then the scheduler hands the chip to the next. A VM waiting for a key gives up its turn at once instead of stalling the others. A shared page of memory, the CIDP, holds each VM's state and lets the VMs see and signal each other. Watch it happen on the Multitasking page.

A way out to the bare chip. When a program needs raw speed, one command (RUNMC) runs a piece of 1802 machine code directly and comes back, about a hundred times faster than the same work in commands, at the cost of holding the chip while it runs.

The Architecture page has the detail: the memory map, the jobs the 1802's own registers are given, RCA's call-and-return technique, and the CIDP.

2What it runs on

STELLAR runs on a COSMAC Elf 2000 (the “Elf2K”), Spare Time Gizmos' modern build of the classic 1970s COSMAC Elf hobby computer:

CPU
an RCA CDP1802 microprocessor.
Memory
32 KB of battery-backed RAM ($0000–$7FFF), which holds STELLAR and its programs; 32 KB of EPROM above it with the Elf2K's own monitor and BIOS.
Front panel
eight toggle switches, a two-digit hex display, the INPUT, LOAD and RUN switches, and the Q light. STELLAR programs can read the switches and INPUT, and drive the display and Q.
Disk/UART/RTC card
a serial port (a 16C450 UART) for the terminal every STELLAR program talks through, and a DS12887 real-time clock that STELLAR can read and set.
Terminal
any serial terminal or terminal program, VT100-style for the full-screen programs.

STELLAR itself fills about 12 KB at the bottom of RAM. Above it sit the shared CIDP page, the four VM cores, and the four 4 KB program blocks at $4000, $5000, $6000 and $7000. Firmware and programs are loaded the same way, as lines of hex bytes (D-lines) that the Elf2K's monitor types into memory.

You don't need an Elf2K to try it: every page on this site runs STELLAR's real firmware on an emulated 1802 in your browser. Start with the Simulator.

3How STELLAR was written

STELLAR's firmware was written straight in hex, with no assembler: every 1802 instruction worked out by hand, typed as bytes, and tested on a real Elf2K. Most STELLAR programs on this site were written the same way, command by command. Programs can also be written in Stellar C, a small C-like language that compiles to STELLAR commands, with a step-by-step guide.

4History

History of the Stellar Programming Layer.

This is a summary of the history of the development of the Stellar programming Layer for the 1802 microprocessor.

My wish for a decade.

I had always wanted to create a programming layer on top of my RCA 1802 Elf2K computer system (designed by Spare Time Gizmos) that I picked up way back in the early 2000’s.

It already has a very simple Basic, and the Forth language, and some rudimentary editors installed. And I had very rudimentary fun with it and its LED’s and its 1861 Pixie chip.

To my shame, in all my years of programming my 1802 systems, I never learned 1802 assembly. I had always programmed in bare-metal machine code and enjoyed it. When I worked for AT&T Bell Labs in the 1990’s, I learned and programmed heavily in Unix and the C programming language, but never assembly. I never had to.

When I discovered there was a simple C programming language compiler for the 1802, I found the resulting code was often very bloated and took loads of memory to do simple things. So I started to dream.

I filled out notebooks full of design ideas and wishes for my little 1802 to try to strive to do.

I imagined making apps that would run on my 1802, on top of a layer that made more math routines and copying routines available. But they were only thoughts on paper. I wished for multitasking, and tried to think of everything it would require to ever become a reality. But I never wrote anything into my elf2k.

And then COVID hit.

Time to Make My Dream a Reality.

So, with months of time on my hands, and no desire to waste it watching TV, I started with the goal of a simple set of 20 extra commands kept in any portion of the available RAM memory that an 1802 program could call using the standard call and return sequence. But those 20 instructions that allowed me more advanced math, memory move, et cetera. quickly became its own layer, running as an interpreter. It had become its own language layer on top of the 1802 machine code. This layer was able to run a new set of commands as its own Language, and it was cool to create simple applications with them.

Those 20 instructions grew into 50, and then started expanding to well over 150 instructions by the end of year 1.

What was unique was the fact I was programming each instruction by hand, in machine code, and tacking it into the programming layer. They were just one byte instructions with added parameters, like memory locations tacked-on. But they were quickly becoming very powerful.

I could never settle on a name for the programming layer.

Then I had the idea one night... of making the programming layer into 4 machines, and time sharing the 4 virtual machines on top of the 1802. FOUR virtual machines, running simultaneously, not by interrupt, but by time share. More about that on another page.

It took a few months to make it work, but in the end, it worked! I could write up to FOUR different Stellar based programs and then run them, and watch as each finished and exited, leaving others to continue until they too finished. I was blown away!

A Multitasking 1802.

I quickly added a series of 16 inter-process commands and communication commands between the virtual machines. And I was totally overwhelmed at how cool this was working.

I finally had an initial name, MPL02 (Multitasking Programming Layer for the 1802).

I wrote hundreds of simple programs using MPL02, but was limited by only being able to communicate with the outside world via the 2 seven segment LED’s and the Q line for sound. I needed to get the UART and VT100 terminal link up working. That was when Claude.ai entered.

Hello Claude!

Up until 2026, I could never get the UART to work for me to actually communicate with my elf2k via a terminal off my Mac. But Claude figured out what I had missed, and in one hour, I was “talking” with MPL02 on my elf2k through a terminal session on my MacBook pro!

From that moment, I began to ask Claude to become an expert in RCA 1802 programming, and to find the flaws in my hand-coded kernel, and it found them! Hundreds of them! And I worked with Claude, training it how I expected MPL02 to work, and Claude made MPL02 sing!

What About a Name?

And then I asked Claude for a proper name, not a technical name like MPL02.

And it came up with STELLAR!

Claude gave me a couple of interesting ideas, but Stellar was the one. It stood for “System for Time-shared Execution on Low-Level Architecture Resources”

One of these days, I will dig up my conversation with Claude about the name because I had to really define what I wanted my elf2k to end up doing, and it was going to be great! I expect to port Stellar to other 8 bit microprocessors someday, so stay tuned!

The First 'Apps'

Lite-writer was the first real app written for the Stellar Programming layer. It was a test of Claude's ability to understand the capabilities of the Stellar code, and the limitations of the 1802 hardware and environment. It ultimately was a proving ground for the functionality of the Stellar opcodes in a real-world application.

Lite-Writer2 has a limited set of functions, but it does them all well. I can write text, save it, recall it, edit it like a simple text editor, all written in Stellar code. I was delighted! But I had only begun!

Working with the CF card

Next to experiment with was the CF card interface on the DISK/UART daughter card of the elf2k. Working with the CF card opened up a whole new world! If Stellar could be expanded into an operating system, it could do almost anything!

So, I just simply asked Claude how do we adapt Stellar to use the CF Card as a disk, and LTOS was born!

Now I could really push the limits of the elf2k and the little 1802 processor!

LTOS

It is an acronym for LighT-Operating System. Okay, so I am not very flashy with my naming, but I like it. I usually pronounce it L-tos, so it sticks.

Claude began to work out how to utilise Stellar’s operating environment and expand it into a switching action that can run an app or a game in Stellar code, or quickly change the environment to the LTOS Operating System without any fuss at all. My elf2k could run dozens of unix commands from an actual command line shell, and then run a Stellar app, as if it all was just one happy family. And it just grew and grew!

All of this shows what the 1802 could have been back in the 1980’s!

Then Stellar on the Web!

I jokingly asked Claude to come up with a set of web pages that would show off Stellar and what it is capable of doing. And www.stellar-1802.dev was born!

The web pages run a full implementation of absolutely every aspect of Stellar and its Apps as well as LTOS, as they run on an actual Elf2K, including sound and VT100 video terminal emulation. And Claude brought the contents of the entire 31k of RAM alive on the main page! It even showed off the four Virtual Machines of Stellar running four different Stellar-based apps at the same time, as they would on a real elf2k. Yes, you can speed it up, but you also can slow it down to a step-by-step through the code, and you can watch every register and memory location in the entire system, blink and change right before your eyes!

Enough of a start. This summary of the history behind Stellar is only a start. There is so much more I want to add, but it will be for another time.

Stay tuned; enjoy Stellar; and happy dreaming about the 1802!

Craig Ledbetter
Ireland
