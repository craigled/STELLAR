01The idea

The RCA 1802 is an 8-bit processor with sixteen 16-bit registers and no stack, no multiply, and no divide. STELLAR is a layer written entirely in 1802 machine code that turns it into a far friendlier virtual machine: a 16-bit accumulator, a multi-byte Math Accumulator with multiply/divide and remainder, a packed-BCD Decimal Accumulator, sixteen virtual 16-bit registers, real call/return and stacks, labels, and structured test-and-branch — exposed as a compact bytecode.

Because STELLAR is an interpreter, it can host several independent programs at once. Up to four virtual machines share the single 1802, each with its own registers and 4 KB program block, taking turns a few opcodes at a time. They talk through a shared page of memory called the CIDP.

The key to the visualizations

A STELLAR VM's registers, accumulators, and flags are not an abstraction layered on top — they are literally fixed bytes in a 256-byte "core" block of RAM (VM 1 lives at $3000). The firmware reads and writes those bytes as it interprets each opcode. So the live core panels on this site are simply a window onto that RAM, updated straight from the real firmware as it runs.

02What runs where

$0000–$2EFF
STELLAR firmware — the interpreter itself (~12 KB of 1802 code)
$2F00–$2FFF
CIDP — common VM interchange page (scheduler + per-VM state)
$3000–$3FFF
VM cores, stacks & labels — one 256-byte core per VM ($3000/$3400/$3800/$3C00)
$4000–$7EFF
Program blocks — up to 4 KB per VM ($4000/$5000/$6000/$7000)

See the architecture page for the full map and the core layout byte-by-byte.

03Faithful, not approximate

The simulator on this site is not a re-implementation of STELLAR's opcodes. It runs the actual flashed firmware on a faithful 1802 emulator, exactly as the hardware does — so what you see stepping through a program is what the real Elf2K would do. The visuals are read directly out of the emulated core RAM.
